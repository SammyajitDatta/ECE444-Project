# ApplyPilot — Sprint 2 integration

React + TypeScript frontend, Flask/SQLite application API and Google authentication,
and the existing Node/Gemini resume worker. Applications are scoped to the signed-in
Google identity. New users are registered on their first successful Google login.

## Branches

Original branches are untouched: `main`, `application_view`, `resume-generation`,
`user_stories`. The complete runnable version is `integration/sprint-2`.

The feature branches are stacked in this order, because they depend on the integrated
Sprint 1 code and authentication:

## Local setup

Use Node 22.12+ (Node 24 recommended) and Python 3.11+.

```sh
git switch integration/sprint-2
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r backend/requirements.txt
npm ci
python scripts/setup_env.py
```

Edit `.env` locally:

- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`: create a Google OAuth **Web application**
  client in Google Cloud. Configure the consent screen and add test users if in testing mode.
  Register `http://localhost:5173/api/auth/callback` as an authorized redirect URI.
  The URI must match exactly, including localhost versus 127.0.0.1.
- `PUBLIC_ORIGIN`: the frontend origin, default `http://localhost:5173`.
- `BRAVE_SEARCH_API_KEY`: optional Brave Search API subscription key for automatic public
  source discovery. Without it, users can enter a source URL directly.
- `GEMINI_API_KEY`: required for the existing AI resume generation and scanned-resume
  transcription. Text-based PDF extraction works without Gemini.
- `FLASK_SECRET_KEY` and `RESUME_WORKER_TOKEN`: generated by the setup script. Do not share them.

```sh
npm run dev
```

Open http://localhost:5173. This starts Flask on 5000, the private resume worker on
127.0.0.1:3001, and Vite on 5173. The legacy standalone client is retained for source
compatibility; use the integrated root command, not the old standalone dev command.

Google manages passwords and account recovery. Signing out ends the ApplyPilot session,
not the user's Google browser session. This does not implement UofT Microsoft SSO.

## Features

- Google OIDC through Authlib with state/nonce/token validation, HttpOnly session cookie,
  server-side session revocation and CSRF protection. Accounts are linked by Google's
  immutable `sub`, never silently linked to an old local account by email.
- Existing application listing, filtering, pagination, document downloads, creation and
  status updates, now isolated per account.
- Job import from public HTTPS URLs or PDF/HTML/TXT files (2 MB). JSON-LD `JobPosting`
  metadata fills structured fields. Text/PDF fallback uses explicit labels where possible
  and preserves the description. Review fields and salary units before saving. Scanned
  job PDFs require OCR before upload; multi-posting pages use the first JobPosting.
- Company/role research displays short direct excerpts, each with source URL and retrieval
  date. It does not generate unsupported company claims.
- Interviewing applications can retrieve explicitly reported questions. Extraction is
  deliberately conservative: the same sentence must name the company and exact role,
  include a report marker such as “interviewer asked,” and contain a quoted question.
  This can miss valid reports. Empty results are explicitly shown, never replaced with
  generated questions. Candidate reports are not independently confirmed facts.
- Resume studio retains the original master-resume input, templates, PDF preview and
  download. Its API now goes through the authenticated Flask gateway. Resume content
  stays in component memory and clears on page exit/reload, as in the original version.

Public retrieval respects robots.txt and skips login walls, inaccessible pages and
unsupported formats. DNS addresses and redirects are validated, connections are pinned
to the validated public IP, and responses have size/time limits. Permission to retrieve
must still be consistent with the source's terms; robots.txt alone is not a license.
Automatic discovery queries disclose the application company/role to Brave Search.
Resume AI processing sends the submitted resume and job description to Gemini.

## Existing database

`db.create_all()` adds the Google identity and session tables without deleting application
records. Pre-existing seeded/local users are **not** automatically attached to Google.
An email collision displays a sign-in error and requires a deliberate administrator-led
migration after confirming ownership. Do not run `backend/seed.py` on valuable data.
For a fresh demo use a fresh SQLite database, not a shared seeded user.

## Deployment

The root dev command is for local development. A production deployment needs a WSGI
server, HTTPS reverse proxy and static serving of `frontend/app/dist`. Proxy `/api` to
Flask, expose no public route to the resume worker, retain persistent DB/upload storage,
and configure the production OAuth redirect URI and `PUBLIC_ORIGIN`. Secure cookies
are enabled for an HTTPS origin. Set a stable random Flask secret before deploying.
No deployment or CI/CD pipeline is included in this change.
